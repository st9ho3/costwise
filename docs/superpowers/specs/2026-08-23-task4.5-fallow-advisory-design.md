# Task 4.5 — Fallow Codebase-Intelligence Advisory Pass (Spec)

**Date:** 2026-08-23
**ClickUp:** [Task 4.5 — Fallow codebase-intelligence advisory pass](https://app.clickup.com/t/868kv7u7r)
**Status:** Ready for planning
**Complexity call:** NOT super-complex — configuration plus a mechanical,
checkpointed triage; an executor runs the plan. (Rule: docs/AGENTS.md,
Model authority.)

## Goal

Fallow (MIT, npm package `fallow`) runs as a permanent ADVISORY check
over the monorepo — dead code, duplication, circular deps, complexity —
and one full pass is run now that Task 4's migration churn is over:
leftovers are deleted where provably safe, judgment items become ClickUp
tasks, and false positives are taught to the config. ESLint (Task 1.5)
remains the only blocking lint gate; Fallow never blocks anything.

## Decisions

1. **Install:** `fallow` as a root devDependency, exact version pinned
   (latest stable at execution time). Same binary everywhere — local,
   CI, agent loops. No GitHub Action wrapper (`fallow-rs/fallow@v3`
   would resolve its own version; one pinned npm dep is one source of
   truth).
2. **Config:** single `.fallowrc.json` (JSONC) at repo root, seeded by
   `npx fallow recommend` (auto-detects pnpm workspaces from
   `pnpm-workspace.yaml` and framework entry points), then tuned.
   Excluded from analysis: generated/vendored output —
   `packages/api-client` generated OpenAPI artifacts (`schema.d.ts`,
   `openapi.json`), `packages/db/drizzle` migration output, `.next`,
   `dist`, `node_modules`.
3. **Suppressions are config-first, with reasons.** False positives are
   recorded in `.fallowrc.json` with a `-- <reason>` comment; inline
   `fallow-ignore` comments only for single-site exceptions. Exports
   that are intentionally external (e.g. consumed by the future mobile
   app) are tagged, not suppressed silently.
4. **Commands:** root scripts `fallow` (full pipeline, human-readable)
   and `fallow:ci` (same pipeline, machine/summary output). Documented
   in `docs/where-to-touch.md` alongside the existing quality gates.
5. **CI:** a second job `fallow` in `.github/workflows/ci.yml` with
   `continue-on-error: true` — it checks out, installs, runs
   `pnpm fallow:ci`, and writes findings to the GitHub job summary. It
   can NEVER fail a PR; the existing blocking `ci` job is untouched.
6. **One full pass, three buckets.** After setup, run `pnpm fallow`
   over the whole repo and place every finding in exactly one bucket:
   - **False positive** → config suppression with reason (Decision 3).
   - **Safe delete** → dead files/exports/imports left by the Tasks 2–4
     migration. Delete only when Fallow reports zero references AND
     build + full test suite stay green afterwards.
   - **Needs judgment** → circular deps, duplication worth merging,
     boundary drift, anything requiring redesign → filed as individual
     ClickUp tasks (Backlog list, CostWise task contract). NOT fixed in
     this task.
7. **⛔ CHECKPOINT before deleting.** The executor posts the complete
   triage table (finding → bucket → one-line why) and stops for review
   by Panos or Fable 5. Deletions happen only after the table is
   approved. (Execution mode: External, per docs/AGENTS.md.)
8. **TDD exceptions (declared):** config files (`.fallowrc.json`,
   `ci.yml`, `package.json` scripts) and pure deletions carry no new
   tests; the gate is the existing suite + build staying green and the
   CI job proving non-blocking on a real PR.

## Acceptance Criteria

1. `.fallowrc.json` exists at repo root; `pnpm fallow` runs the full
   pipeline locally without errors.
2. The `fallow` CI job runs on a PR, publishes findings to the job
   summary, and a failing Fallow run does NOT mark the PR red
   (verified once by observing job status vs PR check status).
3. The full pass is triaged: zero unbucketed findings. Safe deletes are
   committed with build + tests green; each judgment item has a ClickUp
   task; each false positive has a reasoned config suppression.
4. `docs/where-to-touch.md` documents the advisory command and the
   policy: Fallow advises, ESLint blocks.

## Out of Scope

- Making Fallow blocking, in CI or via hooks.
- Paid Fallow Runtime (production execution evidence).
- Replacing or reconfiguring ESLint.
- Executing the "needs judgment" refactors (circular-dep untangling,
  deduplication) — those are the filed follow-up tasks.
- Architecture-boundary preset enforcement — revisit once the filed
  findings show whether drift is actually occurring.
